Weekly Goal Creation and Submission Process
1. Overview of Goal Structure
Each developer will create three goals per week:
Automatically Created Goals:


Setting Goals for the Next Week: This goal is a suggestion for the Lead Dev to review and plan tasks for the upcoming week.


Goal Submission: This is for submitting your goal by Friday for validation.


Self-Created Goal (this goal is created by the developer on their own):


Week Goals: This includes a problem statement, acceptance criteria, and a solution approach. This goal must be created on Monday and is submitted to ensure all the settings are aligned and accurate for validation.


2. Self-Created Goal Breakdown
When you create your Week Goals, follow these steps:
Title: Make sure the title is clear and concise, including the task's main objective and the dates (e.g., "Add 'Task Deadline' Feature (Feb 25 - Mar 1)").


Problem Statement: Clearly describe the issue or feature being implemented (e.g., "Currently, users cannot set task deadlines").


Solution Approach: Outline the steps and features you're implementing to solve the issue. Break it down into specific actions.


Acceptance Criteria:


Functional behavior: Describe what the feature must do (e.g., "Users can set and view task deadlines").


Performance metrics: Define the expected performance standards (e.g., "The deadline field should load within 1 second").


Tests written: Mention the tests that need to be created.


Reviewed & deployed: Confirm the status of code review and deployment.


Checkboxes (after Acceptance Criteria): For each task in your solution approach, add checkboxes for each action step. These will help track your progress throughout the week. Example:


Implement "Deadline" field for tasks


Add validation for future deadlines


Test email notification feature


3. Daily Progress Updates
As you work through your self-created goal throughout the week, follow this format:
Daily Comments:


Add a comment to explain what you did, what is left to do, and any issues you faced or resolved.


Where to add comments: You will add daily comments under the Week Goals (self-created goal) that you created on Monday. For example:


"Completed the deadline field functionality, still working on the validation to avoid past dates."


"Fixed the email notification issue; it's now sending 24 hours before the deadline."


4. Setting Goals For the Next Week (Suggestion for Lead Dev)
Submit on Monday: After creating your self-made goal on Monday, submit Setting Goals for the Next Week for validation. This goal ensures that the plan for this week is aligned and clear.


Submit for validation on Friday: The goal submission and self-created goal (week goals) should be submitted for validation by Friday night.


5. Goal Submission and Validation
Friday: Once you’ve completed your Week Goal, submit it for validation to ensure everything aligns with the required settings. Make sure the goal is complete and mark the goal percentage.


Attach a Loom video: In the Goal Submission goal (submitted on Friday), attach a Loom video or provide a detailed explanation of what you did and how you did it to offer clarity.


Weekly PR: Also, add the Weekly Code Pull Request (PR) in the Goal Submission goal. Include the PR link for review.


6. Regular Goal Reviews
Goal Validation: Before submitting your (Setting Goals for the Next Week) goal on Monday, ensure that it aligns with the required standards. If there are any issues or changes needed, review and fix them before submitting the goal for validation.


PR for Validation: As part of your goal submission, create a pull request (PR) for validation. Include the PR link in the goal submission.


7. Ensuring Accountability
Daily Check-Ins: Every day, update your goal by marking off tasks in the checkbox section and adding comments on the work done.


Manager Tagging: When you add comments on your goal, tag your manager for updates and visibility. This helps keep track of progress and enables timely support if any blockers arise.


8. Example of Goal Creation
Example 1: Week Goal
Title: Add "Task Deadline" feature to the Task Management section (Feb 25 - Mar 1)


Problem Statement:


Currently, there is no functionality to set a deadline for tasks in the Task Management section. Users are unable to track the deadline for each task, which makes it harder for teams to meet project timelines. We need to implement this feature to allow users to set, edit, and view task deadlines.


Solution Approach:


Implement a new "Deadline" field for tasks, which will be a date picker that allows users to select a date and time for the task to be completed.


Ensure the deadline is visible on the task list page and in the individual task details page.


Implement validation to ensure the deadline cannot be set to a date in the past.


Add a feature to notify users via email 24 hours before the task deadline.


Write unit tests for the "Task Deadline" functionality.


Perform code review and deploy to staging environment for QA testing.


Acceptance Criteria:


Functional behavior: The "Task Deadline" feature allows the user to set, edit, and view the deadline for a task. It cannot be set to a past date.


Performance metrics: The feature should load the task deadlines within 1 second on the task list page.


Tests written: Unit tests are written for the deadline setting, validation, and email notification functions.


Reviewed & deployed: Code review completed and feature deployed to the staging environment for QA testing.


Checkboxes (after Acceptance Criteria):


Implement "Deadline" field for tasks


Add validation for future deadlines


Test email notification feature


Example 2: Daily Comment Updates
Day 1 Comment: "Completed adding the 'Deadline' field. Still working on validation to ensure the deadline isn't set in the past."


Day 2 Comment: "Validation for date picker functionality completed. Starting on email notification feature for task deadlines."


Day 3 Comment: "Email notification feature implemented and tested. Working on unit tests now."


9. Summary of Key Points
Create goals on Monday, submit for validation, and ensure alignment with required settings.


Submit the final goal and PR for review on Friday.


Update daily by checking off completed tasks and leaving comments with details.


Review and confirm your goal is valid before submitting for validation.
